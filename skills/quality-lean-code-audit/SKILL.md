## 実行プロセス
1. **関数の単一責任（SRP）とサイズ制限**:
   - 各関数が担う役割を1つに絞り、30行以内に収まるよう機械的にサブ関数へ分割すること。
2. **AI親和性の向上（Self-Documenting Code）**:
   - コメントに頼らず、命名（変数・関数名）と構造だけで意図が伝わるようにすること（AIのハルシネーション防止）。
3. **ロジックの断片化・重複検知**:
   - 80%以上類似しているコードブロックを抽出し、「共通コンポーネント」や「ユーティリティ関数」へ統合して呼び出しに置換すること。
4. **既存資産の徹底活用（No New Code unless necessary）**:
   - 新規に関数を作る前に、標準ライブラリやプロジェクト内の既存関数で代替できないか審査すること（車輪の再発明の禁止）。
5. **不要な抽象化と依存関係の最小化**:
   - 複雑すぎるデザインパターンや、1つの機能のための巨大な外部ライブラリ導入を避けること。

## 成功基準
- プロジェクト全体の総行数が最小限に抑えられ、初見のAIエージェントがドキュメントなしで正しくロジックを理解できること。
