## 実行プロセス（theme.json 参照ロジック）
1. **テキスト要素**:
   - メインタイトルや数値は `text.primary` (#000000) を使用すること。
   - 単位や補足ラベル、チャートの軸ラベルには `text.label` (#626264) を適用すること。
2. **チャート・グラフ配色**:
   - 単一シリーズは `dataColors.blue_series[1]` (#0017C1) をデフォルトとすること。
   - 複数シリーズは `dataColors.blue_series` のインデックス順に適用し、比較対象には `dataColors.grayscale` を用いること。
3. **セマンティック（意味論的）配色**:
   - 成功/増加: `semantic.success` (#197A4B)
   - エラー/減少: `semantic.error` (#CE0000)
   - 注意/警告: `semantic.alert.main` (#FE3939)

## 実行プロセス（レイアウトとアクセシビリティ補強）
4. **ヘッダー構成とKPI配置**:
   - `background.highlight` (#0017C1) を背景にしたヘッダー、または白背景に `text.link` (#0017C1) をアクセントに構築すること。
   - 上部に最大4つのKPIタイルを配置（背景: `visualStyles.card.background` (#FFFFFF), 枠線: `#F1F1F4`）すること。
5. **レスポンシブとアクセシビリティ（補強ポイント）**:
   - モバイル表示時はKPIタイルを1〜2列に自動スタックさせること。
   - コントラスト比（AA基準）を維持し、色覚多様性に配慮するため、色だけでなくアイコンやラベル（+, -）を併用して数値を表現すること。

## 実行プロセス（CSSフレームワークとテーマ戦略）
6. **DaisyUIを利用したコンポーネント管理**:
   - フロントエンドの実装は Tailwind CSS と DaisyUI プラグインを標準として利用し、HTMLのクラス記述によるコンポーネント開発を基本とすること。
7. **青系ベースのカラー固定とカスタマイズルール**:
   - DaisyUIの独自テーマ設定を利用し、基本のカラーコードは**青系**に固定すること。
   - `primary` カラーには `theme.json` に準拠した青色（例: `#0017C1`）を割り当て、アプリ全体の統一感を持たせること。
   - ダークモード等による意図しない色の変更を防ぐため、`<html>`タグの `data-theme` 属性等を用いてテーマを固定する。
   - 特段の変更要件がある場合のみ、個別にカラー設定を上書きすること。
